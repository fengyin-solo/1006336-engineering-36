# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据由
  `frontend/src/data/` 下的种子与规则模块装配（值班交接见下节）。
- 状态流转只允许在 `local-service.ts`（值班交接在 `api/duty-service.ts`）里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 运维值班交接：统一数据层（可搬走的一份）

值班交接的本地数据层不再各环境各写各的，发起交接 / 确认交接 / 登记遗留走**同一套读写规则**，
相关文件：

| 文件 | 职责 |
| --- | --- |
| `src/data/duty-rules.ts` | 班次字典、班组花名册、交接编号推导、核对清单、汇总口径（唯一事实来源） |
| `src/data/duty-seed.ts` | 现行班次排程与早年存量批次，按规则确定性生成 |
| `src/data/migrations.ts` | v1→v2 迁移：早年班次补登、渗漏倒排补录、设备保养台账对齐、种子装配 |
| `src/data/local-store.ts` | 版本化信封、一次性迁移、事务提交（落库失败整套退回） |
| `src/api/duty-service.ts` | 发起交接 / 确认交接 / 登记遗留三个动作的统一读写入口 |

关键规则（均在代码里落实并有 `npm run verify` 核对）：

1. **班次字典**固定为 白班 / 夜班 / 中班；**值班班组**固定三个队、每队固定花名册，
   交接人员签字必须出自本班花名册。
2. **交接编号**由值班日期与班次推导：`DUTY-YYYYMMDD-班次码`（白 D / 夜 N / 中 M），
   样例即按「交接编号 + 班次」生成；同日期同班次天然同号，撞号即同一班次被重复登记。
3. **早年缺班次补登规则**：值班日期早于 `2025-01-01` 的存量，按值班日期「日序奇偶」补
   （奇数日→白班，偶数日→夜班），规则确定、可复算；2025 年之后仍缺班次的**不补、不拿默认值顶**，
   原样进核对清单。存量交接记录一律**按值班日期升序**迁移落位。
4. **核对清单逐条列缘由**：交接编号撞车、班次空着、交接人员与值班班组对不上，三类各算一条
   （一条记录可命中多条）；页面表格、顶部合计、CSV 导出同源同序，条数必然对得上。
5. **两边登记对齐（保养台账）**：登记遗留时可关联设备（如 DEVI-0002），交接记录写「关联设备 /
   现场实测日期」，设备保养台账同步写「关联交接 / 上次保养日」，两边同一事务提交；
   两处取值打架时**以现场实测那份为准**，设备状态按实测日期与保养周期重算。
6. **老的渗漏处置记录按发现日期倒排补录**；早年没登记的字段保持空，**缺值不许拿默认值顶**。
7. **覆盖还是另存**：选**版本化原地覆盖**（信封带 `version`，当前 v2）。理由：本地库只有
   localStorage 单键一个落点，另存旧版本会让三个动作长期存在两套读入口，正是「换台机器数据就变」
   的根因；版本号 + 按交接编号合并保证迁移幂等，重复执行初始化不会冒出多余班次。
8. **落库失败整套退回**：先序列化后写库，任一步失败内存缓存不动，字段不会留在中间态；
   交接与设备台账的批量写同成同败。
9. **汇总与报表读数一致**：待交接 / 已交接 / 有遗留三个指标只有 `duty-rules.ts` 里一份谓词，
   页面卡片、运营概览、导出 CSV 全部读它。

本地开发与线上构建读**同一套种子**（`buildSeedBundle()`，基准统计日固定为 2026-10-01，
与构建日期无关）；依赖通过 `package-lock.json` 锁定，`npm ci` 安装，
`npm run verify` 核对通过才允许构建。

```bash
make verify     # 数据层核对（40+ 条断言：种子、迁移、核对清单、事务回滚）
make build      # 核对 + 类型检查 + 生产构建
make image      # 与线上一致：docker 多阶段构建（npm ci → verify → build → nginx）
```
